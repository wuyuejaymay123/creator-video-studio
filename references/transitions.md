# 转场：给镜头边界一个理由

先决定边界承担什么：对比、时间变化、换步骤、进入示意或回到本人。能清楚直切就直切；动态转场用于帮助理解或完成有意的动作，不按固定秒数插入。

给用户的标题直接说做法，例如“用纸挡住镜头，再切到下一段”。说明谁负责、用户要拍什么、成片会怎样接；英文技术名和内部编号保留在制作数据里。把“保证出入镜头连续性”写成“前后用同一张纸，手机和座位不动，灯光尽量一样”。

## 每个选中的边界都写执行卡

记录相邻的 from/to 行、为何切换、技术与方式（实拍 capture / 后期 post / 混合 hybrid）、触发词或动作、出镜头条件、入镜头条件、连续性要求、剪法、声音、失败时的替代方案。

planned 表示尚未拍齐或核验；ready 必须已看过两端素材；fallback 表示执行替代方案。拍摄前只给建议节奏，拍后定位实际帧并记录源片段及剪点。别把计划的手势写成素材里已经存在。

## 根据能拍到的东西选择

| 技术 | 什么时候有用 | 两端拍摄与后期要点 |
|---|---|---|
| 遮挡 occlusion | 从旧状态到新状态，或实拍进入全屏图解 | A 用手掌/道具覆盖镜头；B 从相近覆盖状态揭开。方向、遮挡色和距离尽量相近，剪在完全覆盖处。避免手撞镜头。缺 B 时可接全屏图形遮罩 |
| 甩镜 whip | 明确换场景或视点，有拍摄条件 | 两端约定成片屏幕方向、运动节奏和落点；在运动模糊区接，B 要有稳定落脚。不要在清晰讲重点时甩动；静态素材无法恢复真实甩镜 |
| 动作匹配 match | 同一行为跨时间继续，或比较两种结果 | 两端对象的位置、尺度、运动方向和动作阶段相近；沿同一动作剪接。手机/道具近景可以单独补拍 |
| 推近/拉远 push / pull | 进入细节或从细节回到全貌 | 区分真实机位移动与后期裁切；后期检查源片分辨率、脸和字幕余量。需要真实景深变化就补拍，不能用放大冒充 |
| 图形接力 graphic_handoff | 真人手势接概念图，或图中物件接真实道具 | 将同一屏幕锚点、轮廓或运动方向交给下一画面；先排手势再做图层。不匹配就用干净直切并保留共同对象 |
| 声音先行/延续 audio_bridge | 让画面换场而句意不断 | 在自然呼吸与声场合适的位置做 J/L 衔接；语义和嘴形对齐，不能让露脸人物说的内容与音轨不同 |
| 直切 cut | 重点应落在话上、证据完整性或素材不适合动态衔接 | 找自然语句边界，保护脸部表情与手势，不让同构图姿态无意跳动；必要时用相关资料覆盖剪点 |

## 原片已拍完时

先查看实际可用的进出动作和音频，再决定技巧。没有动作把手时，使用自然直切、现有物体的图形衔接或合理的后期轻推。需要补拍就单列最少的镜头和理由；其余制作继续推进。用户希望固定机位时，采用手/道具动作和后期方式，甩镜不是默认选项。

动态边界不应吞掉信息。比较两端都要给看清时间；重要否定、数字、按钮点击和结论不要正好藏在遮挡或模糊中。控制转场密度，稳定段给观众恢复阅读位置。

## 在 HyperFrames 中执行

按可用引擎规则实现视频裁切、蒙版、图形匹配或位置变化。用同一时间依据安排素材、音轨和字幕；代码动效在任意时间跳转后应得到相同状态，避免依赖实时随机数或不受时间线控制的 CSS 动画。

先检查边界前、边界中、边界后，再以正常速度连听连看。检查黑帧、重复帧、露底、嘴形、手势方向和结论阅读窗口。记录实际采用的技巧或 fallback；没有看过连续成片时，不称转场已经自然。
