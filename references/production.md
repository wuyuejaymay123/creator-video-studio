# 制作：把计划接到实际素材

## 确认可执行入口

继续当前工程前确认文件、选中的 take、字幕、画幅、输出要求与本次授权范围。制作 HyperFrames 项目时读当前环境的 hyperframes 入口；按任务读其 composition、animation、keyframes、media 与 CLI 指引。不要把本文件里的自然语言当 API 文档，先使用实际工具帮助和版本信息。

只有稿时交出制作计划。实际需要图片时用可用 imagegen，实际要视频时用可用渲染器；工具缺失明确指出，并保留可继续用的资产清单、脚本和工程。

## 以原声定位

检查源片的时长、帧率、分辨率、音轨和方向；读取完整字幕或转写，再校对关键名词、英文、数字、否定词。把计划的触发词定位到真实语音和动作。拍前估时可以被试读覆盖，实际时间不能由字数假装精确生成。

建立可追溯的剪辑记录：片段 ID、源文件与源入/出点、成片起/止、变速或裁切、音轨、字幕和画面用途。仅包装时保持内容；已授权精剪时记录删口误、停顿和段落移动。所有关联时点使用成片时间，保留源时间映射。

## 需要用户补充的截图或视频

写稿和改稿时逐句检查：讲到第三方软件、网站、人物、作品、案例、评价或数据时，是否需要观众看到实际内容才能理解或相信这句话。已有素材先检查并复用；只是提到名字、无需展示时不强求补图。

凡是需要但尚未取得的真实素材，在交稿时明确告诉用户“这里需要你补充截图或视频”，单列“需要你补充的素材”表：

| 对应哪句口播 | 需要你提供什么 | 具体怎么截或怎么录 | 用来说明什么 | 缺少时怎么处理 |
|---|---|---|---|---|
| “点这里，就能下载整个项目。” | 项目页面的截图或录屏 | 截到项目名称和下载入口；若要展示操作，录下打开菜单、点击下载、看到下载结果的过程，开始和结束各停两秒 | 让观众知道按钮在哪里、点击后会发生什么 | 先保留待补录标记，其他部分继续制作 |
| “两种方法的结果差别在这里。” | 同一任务的前后截图或视频 | 两份素材保留相同展示范围，截清要比较的结果；视频注明要用的时间段 | 让观众直接看到差别 | 缺少实测素材时把文案改成方法讲解，并标明示意画面 |

每项写清具体产品或页面、必须拍到的内容、截图还是连续视频、建议时长或开始结束动作；有已知网址或视频时间段也一并列出。截图适合静态信息，连续录屏适合操作步骤与变化过程。请用户提供清晰原图或原视频，保留需要辨认的上下文，遮住无关的账号和私人信息。来源链接用于定位和核查，不自动视为已经拿到可剪辑文件。

同一素材覆盖多句时合并成一项并列出对应台词。在主拍摄表的“观众会看到什么”里同步写“展示你提供的……（待补充）”。只录声音仍可能需要用户提供画面素材，要明确提醒，不能让“仅声音”被理解为无需准备截图或视频。

把这些素材记为 screenshot 或 recording，status 为 planned；source 用用户看得懂的话完整记录补充要求、已知来源和缺失时做法，并通过 segments.assets 关联台词。获得且检查实际文件后更新为 available 和实际路径。

ImageGen 用于明确标注的概念示意；真实界面、第三方原话、作品片段和实测结果需要真实材料。HyperFrames 可对取得的截图或视频做放大、重点标记、对比和转场。缺素材时继续完成稿件与不依赖它的制作；预览标明占位，正式成片交付前补齐，或采用与调整后文案一致的替代画面。

## 资产先满足解释任务

按 [语义设计](meaning.md) 检查所需资产。每项标计划中、已提供或已生成，并给实际路径/来源；示意、教学文本和实测证据明确区分。

图像提示词先拆独立层，再分别调用生成工具；用可编辑文字补标签。检查前景透明边缘、风格一致性和实际可裁切空间。需要人物与图同屏或遮挡关系时才做人像分离；检查头发、手部与运动轮廓，确保遮罩与源片时间一致。

素材不足时按解释目的替换：真实操作缺录屏则列补录清单，机制插画缺生成工具可先用结构图做预览，占位状态明确。不能用想象的界面截图交作真实演示。

## 将一个完整衔接做通，再扩展

选择开头或一个难懂关系连同它的前后镜头做连续片段，验证可读性、语义变化、表情动作和声音落点。已有设计稳定时直接继续，不机械增加样段审批。用户只要求一段修改时，验证修改处和受影响邻接即可。

按逐句记录组装画面。相同概念沿用对象身份与视觉编码；色彩和排版符合本片风格。转场按 [执行卡](transitions.md) 接两端，已有动作不足则执行记录的替代方案。字幕和准确图文保持可编辑，不能靠生成图里的长文字承担关键信息。

长动画用“建立关系—状态变化—稳定结论”的连续过程，实长跟随音轨。音乐和音效让位于主口播；单独检查换场底噪、重复声音、爆音与嘴形。

## 导出可接着改的结果

一般先做 720p 预览，正式版默认 1080p/60fps；用户指定或工程不同则遵循实际要求。正式版从原始资产渲染，源视频低帧率与动画输出帧率分别说明；不将低清预览升格充当原始高清。

导出实际文件、可编辑工程、资产清单、实际采用的剪辑/转场记录，并给简短检查结论。用户已要求完整制作或正式导出时完成已授权范围；完成检查采用 [验收规则](quality.md)。
