# 语义：画面为何这样变化

这是逐句画面设计的判断依据。读完整上下文后再选关系；“但是”“所以”等词只能提示，不能代替理解。允许一组画面连续承接多行。

下方英文分类用于内部判断。交给用户时直接描述眼前会发生什么，例如“左边先放修改前的要求，右边一条条出现修改后的要求，最后两边一起停住，方便比较”。省去关系标签和对象编号；说明“说到哪个词时动”，而不是只写“语义触发”。

## 把含义落实成状态变化

每行记录：表达目的、主要关系、持续对象、起态、变化、终态、口播或动作触发点、稳定阅读窗口。先写观众会看懂什么，再选转场样式。普通真人句可以采用 hold：人物继续自然讲述，没有新增图像。

| 主要关系 | 画面组织 | 衔接的内容依据 |
|---|---|---|
| contrast 对比 | 同一条件、位置和尺度展示差别；只改变比较变量 | 前后对照可保留同一对象的轮廓，或在两栏间对应高亮 |
| cause 因果 | 显示条件、发生的变化、结果；箭头含义明确 | 原因动作产生后续状态，运动方向沿关系推进 |
| sequence 步骤 | 一条路径或同一工作台逐项完成，保留进度 | 上一步的结果成为下一步输入 |
| correction 修正 | 保留问题对象，指出错误关系，再修改 | 在修正词处改变错误连线、状态或标签，留下正确结果 |
| zoom 局部解释 | 全貌定位后聚焦细节，再交代它属于哪里 | 全局与局部用同一个锚点衔接 |
| analogy 类比 | 把抽象关系映射到熟悉物件，说明对应范围 | 形状或动作相接；不能把比喻当真实内部机制 |
| summary 总结 | 收拢前文已经出现的对象与结论 | 延续已有颜色、位置和名称，形成可复用卡片 |
| evidence 证据 | 展示实际材料、出处和有关区域 | 高亮支持当前论点的部分，保留必要上下文 |
| context 情境 | 建立一个能理解问题的具体处境 | 场景变化对应叙事时间或位置变化 |
| hold 保持 | 继续当前真人或稳定资料 | 内容需要听清、读完，直接延续即可 |

“先发生 A，再发生 B”不必然是因果。对比图的面积、数量和速度不能擅自暗示未提供的数据；机制未知时使用明确示意。即便只是装饰性转场，也不能改变证据含义。

## 比较要让观众少做记忆工作

建立固定的比较维度，例如“输入内容是否齐全”。先指出看哪里，再在同位置显示变化；必要时最后并排停留。真实前后图保持可比较的裁切和尺度。没有实测的提升幅度，不用柱长、秒表或百分比制造结果。

步骤之间保留完成状态；讲修正时让观众看见改的是哪一处；总结时回收正文出现的对象。转场若同时改变位置、配色、对象和尺度，先减少无关变化。

## ImageGen 与 HyperFrames 的分工

难懂概念优先画出来，可做多个互相关联的图层或场景，不设置机械的图片配额。每张图回答一个解释问题；纯装饰无法帮助理解时可省略。

ImageGen 负责有视觉表现力的物件、情境、材质与隐喻。每次生成说明主体、构图、风格、画幅、透明需求、文字留白和用途；需要独立运动的元素分别生成。实际资产有文件后才标生成完成。一张平图没有被遮挡背景或独立部件，不能声称能直接拆成真实三维场景。

HyperFrames 负责精确文字、关系线、蒙版、布局、强调和时间。图片需要动效时一并安排；长解释段让同一组素材依次建立关系、转变状态、聚焦、汇总，持续时间贴合原声。每个变化后留可读的终态，不把“持续有东西动”当作解释完成。

软件按钮、实际界面、数据与操作证据使用真实录屏或截图。生成情境可用，证据不能生成。类比图标明示意范围，图中的中文标签后期绘制以便校对。

## 一个跨句例子

台词：“要求散在聊天里。”→“先分清什么时候用、怎么做、怎么检查。”→“下次用新任务试一下。”

画面：相同纸条散在桌上 → 分到三个区域，标签后期出现 → 整理成册；随后换一张测试任务卡进入。纸条形状和身份保持一致，“分清”触发分类，“新任务”触发测试对象出现。说明册是类比，不代表某个工具内部真按三格运行。

两句之间若仍在讲同一个对象，直接延续其状态；只有视角或场景确实改变时，才把边界写成 [转场事件](transitions.md)。
