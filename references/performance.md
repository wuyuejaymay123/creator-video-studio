# 表演：让说话意图可见

## 提示要少而准确

每行先判断意图，再给一个最有用的提示：把一个词说清楚、在回答前停一下、让目光回到镜头，或用手接住将出现的对象。平常句可以写“正常说，手放松”。复杂台词先拆意群，避免同时要求挑眉、转头、摆手、变速。

| 说话意图 | 可尝试的表演 | 与画面的联系 |
|---|---|---|
| 说中一个麻烦 | 略带疑惑，问题后短停 | 给观众识别情境的时间 |
| 给答案或发现 | 关键词更明确，语气略提亮 | 答案出现时完成一个轻动作 |
| 比较 | 两边语气同样清楚，差别落在关键词 | 手与画面对象使用一致的左右位置 |
| 分步骤 | 每项起始稍停，可用手指数 | 数量与实际步骤对应 |
| 提醒条件 | 语气放稳，动作收住 | 让注意回到关键限制 |
| 邀请保存或继续看 | 像给一个有用建议 | 清单或后续内容已经具体呈现 |

这些是选择项。按本人习惯调整，坐姿、单手或仅眼神与声音都可表达。动作不必夸张，也不需要每句话重复表情。

## 露脸与仅声音分别指导

露脸默认固定景别。变化首先来自表达；需要镜头或人物动作的转场，按 [转场执行](transitions.md) 安排专门的出点与入点。用户要求整段固定机位时，用物体、手势或后期画面衔接。

仅声音行指导重音、语速和停顿；可见表演写在前后真正露脸的行。一个意群内部发生露脸状态变化就拆行，用户表格始终明确写“露脸”或“仅声音”。

如果用手势接图，先定成片屏幕位置再定手的位置。确认自拍镜像不会颠倒左右；留出字幕和证据区。手掌停住可作为图片展开的触发点；收手或回望镜头可作为返回实拍的衔接点。

## 给拍摄者的表

主表只保留：第几句、你要说的话、露脸/仅声音、你怎么说怎么做、观众会看到什么。用“像和朋友吐槽，说完停一下”“把纸靠近镜头，直到挡住整个画面”这样的日常表达。不要让用户先学会“锚点、出点、意群、触发”等术语才能照拍。

需要解释画面时，写出用户能够想象的过程，例如“三张纸条从你刚才手掌的位置出现，再分成三堆”。JSON 字段和具体合成参数供 Codex 制作时读取，用户默认看到简单说明。

提示用可执行语言：“说到‘缺一项’时略停”优于“表现高级的张力”。口播内容不为配合动画被硬拉长；确需阅读或动作时间时，在计划里留自然停顿，实际剪辑时校准。

拍摄前先自然试读一遍，重点排练开头和转场。转场镜头记录所用道具、屏幕方向、构图及衔接动作；按需给动作前后各留约一秒余量，这只是拍摄建议。选用自然流畅的 take，接点对不上优先使用替代剪法。
